# Completed-round sharing

## Behavior and architecture

Round Details (`/rounds/[id]/stats`) offers a secondary **Share Round** icon in the top-right action group, immediately before Edit and Delete. Its accessible label and tooltip identify the action. It opens a scrollable preview without a visible header; while the PNG renders, the preview uses the existing branded GolfIQ app loader with an accessible status and no visible loading copy. The bottom uses the app's equal-width split-button pattern with Cancel on the left and Share or Retry on the right. Share keeps the same label when the browser falls back to downloading the PNG. The dialog retains an accessible Share Round label. The existing modal accessibility hook traps keyboard focus, handles Escape, restores focus, and locks background scrolling. Safe-area insets are preserved. Returning from a share sheet does not refresh away the open preview.

The PNG is drawn directly onto a fixed **1080 Ã— 1350 canvas**. It is not a screenshot and does not depend on viewport size or device pixel ratio. Desktop and mobile use the same renderer, coordinates, content, and generated image; the browser only scales the completed PNG proportionally to the available dialog width. This uses browser capabilities, the existing fonts and same-origin wordmark, with no screenshot/image-generation dependency, new API, upload, or server image cache. The renderer reads Inter, Space Grotesk, colors, borders, `--gap`, `--gap-small`, padding, and `--border-radius` from the app-wide CSS tokens. Score classification and the score-result size, outline, border, square radius, font, and optical offset are shared with the post-round scorecard. Grid lines, score marks, and centered text snap to whole export pixels so the full-size PNG stays sharp. Preview and shared file use the same generated bytes.

### Card hierarchy

1. A centered GolfIQ wordmark masthead.
2. A full-width metadata stack with the signed-in owner's first and last name, prominent course name, Lucide calendar/date, and the existing holes, tee, rating/slope, and round-context pills. The generic session username is never used.
3. A separate right-aligned score section with the dominant total score and blue relative-to-par value. Unreliable relative-to-par values are omitted, and neither value has a supporting label.
4. One reusable scorecard renderer draws one nine-hole band or front-nine and back-nine bands for 18 holes. OUT and IN totals and the shared score-result circles and squares are preserved.
5. Up to six non-null stats appear in equal-width centered columns: FIR, GIR, Chips, Bunker, Putts, and Penalties. Tracked zeros are retained.
6. Premium cards include a separated Strokes Gained section with a compact handicap-comparison note and equal-width columns for finite Off the Tee, Approach, Short Game, Putting, and Penalties values. Positive values are green, negative values are red, and zero is neutral. Free cards preserve the existing SG entitlement.
7. Subtle tagline and canonical `golfiq.ca` attribution.

Long course names wrap to two lines and are limited to 120 characters. There is one template with optional data-driven sections. The previous long round-insight paragraph is not included.

## Authorization, entitlements, and privacy

- Preview creation freshly requests the existing ownership-checked stats API with `credentials: include` and `cache: no-store`.
- Sharing requires the existing ownership-checked completed-round stats response for a saved 9/18-hole round with a positive score. Sparse hole details do not hide sharing for aggregate or older completed rounds. Live session data is never used.
- No new scoring, handicap, strokes-gained, insight generation, or entitlement calculation is introduced.
- Strokes-gained values enter the card contract only when the existing `useSubscription` result is Premium. Raw SG messages never enter the contract.
- The pure card builder selects only the signed-in owner's bounded display name, course, date, tee/rating metadata, context, score, relative-to-par, selected stats, permitted SG components, and the public marketing URL. No email, account identifier, notes, round IDs, GPS, billing, or other profile data is exported. The display name is intentionally included so recipients can identify whose round was shared.
- Browser object URLs are released on close/retry. Native files are written to the app cache and deleted after sharing resolves, fails, or is cancelled. A process termination can leave a transient OS-cache file until cache eviction.

## Sharing and native setup

- iOS uses `@capacitor/filesystem` **8.1.3** and `@capacitor/share` **8.0.1**, both compatible with the repository's Capacitor **8.4.2**. Share receives a `file://` PNG and short score/course/context text with the canonical URL.
- Web uses `navigator.canShare({ files })` and `navigator.share` with a prepared PNG File, preserving click activation. Unsupported environments download the PNG. Sharing errors retain the preview and offer another attempt/download; cancellation is not reported as a failure.
- Destination apps control whether accompanying text survives. No direct social API is used.
- `npx cap sync ios` was run. SwiftPM references were added and Windows-generated separators normalized to preserve macOS paths. The existing exact Capacitor 8.4.2 reference remains.
- `ios/App/App/PrivacyInfo.xcprivacy` declares the Filesystem-required FileTimestamp reason **C617.1** and is included in the Xcode Resources phase, following the [official Filesystem guidance](https://github.com/ionic-team/capacitor-filesystem#apple-privacy-manifest-requirements).
- On the release Mac: run `npm ci`, then the existing `npx cap sync ios`/Xcode release workflow. Resolve Swift packages and build/install a new native binary; the hosted web update alone cannot add native plugins. Xcode compilation and physical-device sharing still require validation.

## Analytics

`round_share_opened`, `round_share_invoked`, and `round_share_failed` use the existing capture helper and event constants. Properties describe round type, hole count, optional-section availability, platform, method, and failure stage. No event claims publication or successful delivery.

A share-event-only allowlist runs in PostHog's `before_send`, removing automatic URLs/referrers and other unapproved properties as well as explicit private fields. Existing pseudonymous identity/delivery fields remain. Other event behavior is unchanged.

## Deferred

Multiple templates, editing, photos, public round pages, referrals, social feeds, and direct destination APIs remain outside this MVP. Font rasterization can differ slightly across operating systems; PNG dimensions and layout coordinates remain fixed.
