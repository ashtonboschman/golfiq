# GolfIQ security and network compatibility audit

Audit date: 2026-07-29  
Application: `https://www.golfiq.ca` (canonical), `https://golfiq.ca` (redirect)  
Repository: Next.js App Router, TypeScript, Prisma/Postgres, NextAuth, Stripe/RevenueCat, PostHog, UploadThing, Google Maps, PWA and Capacitor

## Scope, method, and control boundary

This was a read-only audit of production infrastructure plus a repository audit and a set of deliberately narrow code changes. It covered the complete tracked file inventory, all 61 API route files, the three files containing Server Actions, authentication and entitlement helpers, Prisma models, browser integrations, PWA behavior, public trust pages, dependencies, build output, and repository-visible deployment configuration.

The audit also inspected the connected Vercel project's production deployment and made unauthenticated HTTP/DNS observations. It did **not** change Vercel, DNS, production environment variables, URL categorization records, or an employer's security policy. The connected Vercel interface did not expose environment values, firewall rules, deployment protection, DNS configuration, or WAF configuration. The local Vercel CLI was not authenticated. Those items remain checklist work below.

There are three distinct control boundaries:

1. **Repository controls:** application code, dependency versions, metadata, fallbacks, public files, response logic, and repository-defined headers.
2. **Hosting/domain controls:** Vercel project settings, environment scopes, deployment protection, WAF/rate limiting, custom-domain configuration, DNS, TLS, and email authentication.
3. **External controls:** URL category databases, corporate SASE/SWG policy, TLS inspection, endpoint policy, and employer allow-lists. Code cannot compel any of these systems to permit GolfIQ.

No attempt was made to bypass, disguise, or weaken enterprise security controls.

## Executive summary

**Overall residual risk: Medium-High.** Before the low-risk changes, the dependency audit included two critical advisories and the local development environment globally disabled TLS certificate validation. The critical dependency advisories were removed with patch updates. A follow-up pass also removed the TLS override, corrected database CA handling, and updated four safe transitive resolutions. The final production-dependency audit reports 7 affected package entries (0 critical, 3 high, 4 moderate); the full development audit reports 40 entries, with one `brace-expansion` issue accounting for 33 of the 36 high-severity lint/test package entries. The underlying reachability analysis is below. Authentication session revocation, profile email changes, Stripe webhook replay handling, process-local rate limiting, CSP deployment, privacy disclosures, and external platform controls still require designed follow-up.

The reported enterprise block was not caused by an invalid font response. The exact resource was a same-origin, locally bundled IBM Plex Sans variable font generated by `next/font`. Live inspection returned HTTP 200 with `Content-Type: font/woff2`, immutable one-year caching, and permissive static-asset CORS appropriate for a public font. The gateway classified the site as **Uncategorized** and the activity as **Download**, then denied it under external policy. That decision cannot be fixed in code. IBM Plex Sans was unused by GolfIQ's CSS, however, so its import and preload were removed; system fallbacks were strengthened so blocked brand fonts do not make the interface unusable.

The application already has useful controls: authenticated API helpers with private/no-store responses, extensive route contract tests, ownership checks on round and user resources, signed Stripe/RevenueCat webhooks, a safe redirect helper, server-side course API credentials, feature-detected geolocation and Maps loading, and a service worker that avoids private/API navigation caching. Public title/description, canonical URL, Open Graph/Twitter data, structured data, robots, sitemap, About, Contact, Privacy, and Terms are present.

Highest-priority actions are:

1. Deploy the verified database TLS change and validate it in Preview, then Production. The project owner confirmed from the Vercel dashboard that `NODE_TLS_REJECT_UNAUTHORIZED` is absent and `DB_CA_CERT` is configured; the local override has been removed and a verified database query now succeeds.
2. Track the unresolved Next.js advisory and remaining dependency tree; upgrade as fixed compatible releases become available.
3. Add revocable sessions and atomic, hashed password-reset tokens; require recent authentication for password, email, and account deletion changes.
4. Replace process-local rate limiting with Vercel WAF and/or a durable store, and add Stripe event-level idempotency.
5. Stage a measured CSP in Report-Only mode, reconcile privacy disclosures, and complete Vercel/DNS/category-vendor review.

## Font and static asset investigation

The exact denied URL mapped to a 40,240-byte IBM Plex Sans variable WOFF2 generated by the root `next/font/google` configuration. It covered normal weights 100-700 and used `font-display: swap`. GolfIQ's CSS did not reference the IBM variable, while the root `<body>` caused Next.js to preload the file.

The live resource on 2026-07-29 returned:

```text
HTTP 200
Content-Type: font/woff2
Cache-Control: public, max-age=31536000, immutable
Access-Control-Allow-Origin: *
```

It was a same-origin request from `www.golfiq.ca`, so the static CORS header was not required for the normal page load but is appropriate for a public immutable font. HTTPS and the certificate chain were accepted by the audit client. The evidence points to a category/activity policy denial, not malformed content or transport.

The root font import was removed because it was unused, not to disguise traffic. The remaining Inter and Space Grotesk brand fonts have explicit system fallbacks in `app/app.css:302-306`. With either or both WOFF2 files blocked, layout typography changes but navigation, forms, round entry, and analytics remain functional. Local production verification confirmed the old `03fc...` reference is absent from the generated homepage.

## API, Server Action, authentication, and cookie review

The 61 route files were classified as authenticated/user-owned, admin-only, signed webhook, deliberately public auth/PWA, or internal bootstrap endpoints. Server Actions occur in the two admin GPS pages and `lib/gps/mappingActions.ts`; each action path calls `requireAdmin`. Tests cover many API contracts and ownership failures.

NextAuth uses JWT sessions with a 30-day maximum (`lib/auth-config.ts:334-338`) and framework-standard cookies. On production HTTPS, NextAuth v4's secure cookie variants are `HttpOnly`, `Secure`, and `SameSite=Lax`; this should be confirmed from an actual production sign-in response because repository configuration does not override cookie objects. OAuth redirect handling uses the framework plus a repository helper that accepts only same-origin relative paths (`lib/auth/redirect.ts`). No refresh/OAuth tokens were found in browser storage.

High-risk follow-up should be tested as complete flows:

- register, verify, credentials sign-in, forgot/reset, password change, logout, and cross-device session revocation;
- Google and Apple initiation/callback/error flows;
- email change verification and rollback;
- account deletion with recent-auth challenge;
- Stripe and RevenueCat duplicate/out-of-order webhook delivery;
- every object route using another user's ID;
- chunked oversized request bodies and upload type/content mismatch.

Prisma parameterization and schema validation reduce conventional SQL injection risk. The more relevant risks are authorization drift, mass assignment, replay, and excess data/logging. Continue to use explicit field schemas rather than spreading request bodies into Prisma.

## PWA and caching review

`public/sw.js` separates versioned static and public-page caches, does not cache API/auth paths or authenticated/private navigation, checks sensitive request properties, provides `/offline.html`, claims a new worker, and deletes old cache names. `PwaManager` registers with a version query, observes updates, and now handles unavailable/throwing storage and missing `matchMedia`.

Live responses observed:

- `/_next/static/*`: immutable one-year cache;
- homepage: private/no-cache/no-store at the current production deployment;
- `robots.txt`, sitemap, manifest and `sw.js`: successful, correct content type, revalidation-oriented caching;
- shared API responses: application helper sets `no-store, private, max-age=0`.

Do not cache authenticated pages for offline use unless data isolation, logout cleanup, and device-sharing threats are explicitly designed. Preserve network-only API behavior. Test old tabs after every deployment because Next chunk URLs are immutable and a stale HTML document can reference removed chunks even with a well-behaved worker.

## Environment variables and secret handling

No secret values are included in this report. The final tracked-file scan did not match common private-key, cloud credential, Stripe live secret, GitHub token, or Slack token patterns. `.env*` and `.vercel` are ignored. The tracked certificate is a public CA certificate, not a private key.

The local `NODE_TLS_REJECT_UNAUTHORIZED=0` entries were removed on 2026-07-29. Without the override, the database correctly failed with `self-signed certificate in certificate chain`. `lib/db.ts` now passes either base64 `DB_CA_CERT` or local `DB_CA_CERT_PATH` directly to `pg` with `rejectUnauthorized: true`, removing conflicting URL-level SSL options that otherwise replace the explicit `pg` SSL object. The actual Prisma adapter then completed a verified-TLS `SELECT 1`. The connected interface did not expose Vercel environment names and the local CLI had no credentials, but the project owner subsequently supplied the dashboard names and scopes: `NODE_TLS_REJECT_UNAUTHORIZED` is absent, `DB_CA_CERT` is present, and application secrets are limited to Production and Preview. ## Security header recommendation

### Baseline headers

Deploy these after integration testing. Vercel already injected HSTS and several baseline headers in the live observation; defining ownership explicitly avoids relying on undocumented drift.

```text
Strict-Transport-Security: max-age=63072000
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(self)
X-Frame-Options: DENY
Cross-Origin-Opener-Policy: same-origin-allow-popups
```

Notes:

- Do not add `includeSubDomains` or `preload` to HSTS until every subdomain is inventoried and permanently HTTPS-capable.
- Keep `X-Frame-Options: DENY` while also using CSP `frame-ancestors 'none'` for older clients.
- `same-origin-allow-popups` is safer for OAuth/payment popups than `same-origin` until Google/Apple/Stripe flows are verified.
- Do **not** enable `Cross-Origin-Embedder-Policy` yet; Google Maps, external avatars, analytics, and payment/auth integrations are not designed for cross-origin isolation.
- Do not set a global restrictive `Cross-Origin-Resource-Policy` until Maps, avatars, OAuth, uploads, and Capacitor shells are tested. Prefer `same-origin` only on private API/HTML responses and explicit `cross-origin` where a public asset genuinely needs it.
- Next's `X-Powered-By` is disabled in `next.config.ts:5`.

### Phase 1: Report-Only CSP

Create a sanitized, rate-limited `/api/security/csp-report` endpoint **before** configuring this header. The endpoint does not exist today. Do not log cookies, full query strings, usernames, tokens, or arbitrary report bodies.

```text
Content-Security-Policy-Report-Only: default-src 'self'; base-uri 'self'; object-src 'none'; frame-ancestors 'none'; form-action 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval' https://maps.googleapis.com https://*.googleapis.com https://*.gstatic.com https://us-assets.i.posthog.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' data: https://fonts.gstatic.com; img-src 'self' data: blob: https://*.ufs.sh https://utfs.io https://*.googleapis.com https://*.gstatic.com https://*.google.com https://*.googleusercontent.com; connect-src 'self' https://us.i.posthog.com https://us-assets.i.posthog.com https://*.googleapis.com https://*.gstatic.com https://*.google.com data: blob:; frame-src https://*.google.com; worker-src 'self' blob:; manifest-src 'self'; media-src 'self' blob:; upgrade-insecure-requests; report-uri /api/security/csp-report
```

This is a **starting inventory, not an enforcement-ready final policy**. It deliberately avoids a blanket `https:` source. Wildcard subdomains are limited to provider families whose exact runtime hosts can vary; replace each with HAR-observed hosts where practical. Add Google/Apple/Stripe/RevenueCat origins only if browser CSP reports show in-page requests; top-level navigation is not governed by `connect-src`.

The temporary `'unsafe-inline'` covers Next inline bootstrap/JSON-LD/root theme code and styles. Google Maps' allowlist-mode compatibility may require `'unsafe-eval'`. Neither is an acceptable long-term target. Google recommends nonce-based strict CSP for Maps, and Next.js documents nonce propagation through its request rendering.

### Phase 2: nonce-based enforced CSP

After Report-Only telemetry is clean, target:

```text
Content-Security-Policy: default-src 'self'; base-uri 'self'; object-src 'none'; frame-ancestors 'none'; form-action 'self'; script-src 'self' 'nonce-{REQUEST_NONCE}' 'strict-dynamic' https://maps.googleapis.com https://*.googleapis.com; style-src 'self' 'nonce-{REQUEST_NONCE}' https://fonts.googleapis.com; font-src 'self' data: https://fonts.gstatic.com; img-src 'self' data: blob: https://*.ufs.sh https://utfs.io https://*.googleapis.com https://*.gstatic.com https://*.google.com https://*.googleusercontent.com; connect-src 'self' https://us.i.posthog.com https://us-assets.i.posthog.com https://*.googleapis.com https://*.gstatic.com https://*.google.com; frame-src https://*.google.com; worker-src 'self' blob:; manifest-src 'self'; media-src 'self' blob:; upgrade-insecure-requests
```

A request nonce normally forces affected Next.js pages into dynamic rendering, must be forwarded through the framework, and can reduce full-page CDN caching. It must be generated per request, never exposed as a stable environment value. Test Metadata/JSON-LD, OAuth, PostHog, Maps, UploadThing, PWA registration, Capacitor, and every public page before enforcement.

### Cache directives

- Authenticated HTML/API: `Cache-Control: private, no-store, max-age=0`.
- Auth, reset, verification, webhook, profile, subscription, export: `no-store`.
- Hashed `/_next/static/*`: `public, max-age=31536000, immutable`.
- `sw.js`, manifest, robots, sitemap, HTML: revalidate rather than immutable.
- Public marketing pages may use controlled CDN caching only after confirming they never include session-specific output.
